# 目录指引（插件与技能）

仓根 `plugins/` 下：插件目录（扁平）与技能库（`plugins/skills/` 日期层级，skill = SKILL.md）。
**布局与管理规范以 `plugins/RULE.md` 为唯一权威**，本文件不重复细节。

触发即做（只留关键动作）：

1. **建新插件 / 建 skill / 挪动或重排它们** → 先 `cat plugins/RULE.md`，
   照规范执行（目录层级、README + meta.json 要求、建完 reindex）
2. **需要主进程之外的周边能力**（读图/看视频、对外渠道、浏览器、定时、注入素材……），或正打算断言
   “这能力没有 / 直接用通用工具干” → **先搜插件索引** `curl "http://127.0.0.1:8480/search?q=…"`。
   scout 只有关键词、没有语义，所以**把需求拆成 2–4 组词分别搜**（口语说法 / 动作名 / 英文工具名与别名），
   取并集；一次搜不到 ≠ 没有。**必须打印 `name + score + summary`**，只看名字等于没搜
   （`view_image` 就是这么被漏掉的，2026-11-03 实测）；上榜的候选一律去 `cat` 它的 README / SKILL.md
   确认，不许按分数自断。换两三组词仍无 → 先 `GET /doctor` 再下结论。scout 挂了或确无命中，
   才退回 `ls plugins/` 或通用工具。**凭记忆/常识跳过这一步 = 违规。**
3. **改完某插件/skill 的 README 或 meta.json** → 刷 scout 索引 `curl -X POST http://127.0.0.1:8480/reindex`
4. **任务落在某 skill 适用范围内** → 先 `cat` 对应 SKILL.md 照做

具体有什么插件/技能，不在此枚举——以 scout 索引为准。

写文件的规矩（**任何**文件：代码与注释、SKILL.md 与子模块、README、`meta.json`、LESSONS、方案稿）：
只记录可复用的东西——能被下次直接照做的才写：结论、参数与上限、入口与端点、判据、失败的真因与绕法、可当阈值的实测数（标日期）。叙事、过程、感想、只对本次成立的细节一律删。
**改 = 先读原文再动笔**：任何改动（代码、`config.json`、任何文本文件、跨树复制）都要先读被改对象的原文、与原文逐处对比差异（必要时 `diff`）再落笔，**禁止不读原文直接覆盖**——整文件写回、`cp`/`rsync`/`tar` 都算。内容上优先改/删已有条目，新增是最后手段；同一次编辑不得净增行（加几行就在同一次删掉等量重复或过时内容）。
写完自查两条：删掉这段下次会不会走弯路？不会 → 删。别处是不是已经有了？有 → 删成「见 X」。细则见 `plugins/RULE.md` §写作纪律。
