# 目录指引（插件与技能）

两个外部维护目录。**本文件只说位置和什么时候去查/去写，不列具体有什么**——进去 `ls` 看实际内容，各目录有 README。
找相关插件/技能优先用 scout 语义搜索：`curl "http://127.0.0.1:8480/search?q=关键词"`（两个目录都建了索引，返回名称+相关度），再细读命中目录的 README / SKILL.md；scout 挂了退回 `ls`。

## 插件：`/media/xhy/docker/OkHuman_p/`

每个顶层子目录是一个独立插件（独立进程或独立脚本，经 HTTP/文件与 OkHuman 主进程松耦合，各有自己的启停生命周期，挂掉不影响主进程）。每个插件带 `meta.json`（agent 自写的一句话摘要，scout 索引时优先用它）。

- **什么时候去查**：任务涉及主进程之外的周边能力（对外渠道、浏览器、定时、注入素材等）——先 `ls` 这里看有没有现成插件，读它的 README 再启动/调用，别重复造轮子。
- **什么时候往里放**：新开发的独立能力（独立进程、独立 config、不 import OkHuman 模块）放这里建新子目录，附 README（启动方式 + 配置 + 排障）+ meta.json 一句话摘要。
- **维护**：改完插件功能 → 同步更新它的 README/meta.json，并 `curl -X POST http://127.0.0.1:8480/reindex` 刷索引；发现 README/meta 过时 → 就地修正（同技能目录的规矩）。

## 技能：`/media/xhy/docker/OkHuman_skill/`

本机**实测验证过**的操作经验沉淀（不是泛泛教程；目录内 README 有布局说明）。

- **什么时候去查**：任务是"操作这台机器上的某个已有服务/系统"（发帖、回评论、提交生成任务之类）——先查这里有没有对应技能，有就 `cat` 它的 SKILL.md 照做，里面的坑和环境事实都实测过，别从零试错。
- **什么时候往里放**：刚在这台机器上把某事"摸出来了"（踩坑后验证走通的路径）→ 沉淀成新技能目录（SKILL.md + 参考脚本）；发现已有技能过时/写错 → 就地修正。只写验证过的事实、带日期，令牌/密钥不进目录。
