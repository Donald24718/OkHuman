# OkKnowledge v0 — 表示规范

日期：2026-10-06　依据：`可行性报告.md` §12 §13 §14
原则：**能实现的最小集合**。凡是 v0 用不到的，一律不设计。

---

## 1. 三条不变式（不可协商）

1. **ID 永不改指。** 语义变化 → 发新 ID + `supersedes` 边。改含义 = 事故。
2. **每条记录必须有出处。** 无出处的条目视为不存在。
3. **硬约束优先。** 任何软分数不得覆盖二值约束。

---

## 2. 节点（实体 = 命名子图的闭包）

```
node := {
  id          : u64            # 不透明，永不复用
  kind        : u16            # 类型（见 §4）
  version     : u32
  supersedes  : u64 | 0        # 取代哪个旧 ID
  body        : span           # 指向子图（§3）；0 = 原子
  constraints : span -> [constraint]   # 挂在任意嵌套层，用即生效
  prov        : {source, verified, ts} # 见 §6
  reuse       : u32            # 复用计数（遗忘与合并的依据）
  last_used   : u32
  canon_hash  : u64            # 规范形哈希，用于同构去重（§7）
}
```

**原子实体也允许**（`body=0`）——v0 不强迫一切都有内部结构，但通不过 §8 可实例化测试的原子会被优先淘汰。

---

## 3. 关系 = reify（关系本身是节点）

`我吃苹果` 不是 3 项，是 **6 项**：

```
n1 = node(kind=关系.事件, id=E)          # 事件枢纽
n2 = node(kind=实体.人,   id=X)          # 我
n3 = node(kind=实体.物,   id=Y)          # 苹果
e1 = edge(src=E, dst=X, role=agent)
e2 = edge(src=E, dst=Y, role=patient)
e3 = edge(src=E, dst=关系.吃, role=lemma)
```

**角色是边，不是属性。** 这样角色本身也能挂约束、带出处、被去重。

边记录：
```
edge := { src:u64, dst:u64, role:u16, prov:{...}, weight:f32 }
```
`weight` 由**共现统计**更新（两端在同一条**验证通过**的轨迹里一起出现 → +1）。不是 LLM 给的，不是人给的。

---

## 4. 类型：ID 不透明，类型走边

**不要把类型路径烧进 ID。** 反例：`实体.电子.消费品.手机` 一旦本体调整，ID 就作废，违反不变式 1。

正确做法：
- ID **不透明**（u64）；
- 分类是**边**：`is_a(n, 类别.消费品)`；
- 可读路径 `实体/消费品/手机#0001` 是**从 is_a 边算出来的视图**，不是存储键。

这样重分类 = 改一条边，ID 不变。**同时保留组合线索**（同前缀 = 同子树），因为路径视图就是前缀。

类型是**承重的**：它定义"这个能嵌进那个吗"（§5）。v0 只要求 `kind` + `is_a` 两层，不做类型推断。

---

## 5. 组合 = 在类型匹配处做子树替换

```
compose(A, B) 合法 ⟺ A 的某个 slot 的 kind 与 B 的 kind 兼容（is_a 闭包内）
```

v0 只做**显式槽**：节点的 body 里预留带 kind 的空位。不做自动槽推断。

**环规则：名字处允许环，展开处禁止环。** 即 `body` 引用链必须无环（可证终止）；`edge` 图可以有环。

---

## 6. 出处（source）四类

| source | 含义 | 默认可信度 |
|---|---|---|
| `import` | 结构化导入（代码、schema、Wikidata、配置） | 高（外部接地） |
| `master` | 主人直接给的 | **最高** |
| `verified` | 系统行动后被环境验证的后果 | 高（可复现） |
| `proposed` | 系统自己提议、未验证 | **低**，且不得参与硬约束 |

**v0 明确排除 `llm` 这一类**（主人定：不要外挂）。将来若走读法 A，自训部件产出的条目归入 `proposed`，永不自动升为 `verified`。

---

## 7. 存储与去重

- **扁平数组 + ID 索引邻接表，SoA 布局，mmap。** 不用任何数据库、不走进程边界。
- 目标：活跃子图常驻末级缓存。
- **去重按规范形哈希**：把子图按 (kind, 角色多重集, 子 canon_hash) 递归规范化 → 哈希。同哈希 = 同构候选 → 生成**合并提议**（不自动合并，提交走人）。

---

## 8. 准入与遗忘

**准入门（可实例化测试）**：一条记忆要进活跃图式库，必须能指出**槽位**，且换填充物后仍成立。通不过 → 只进实例日志，等着降级。

**价值函数**（可算）：
```
value = reuse × recency_weight / size_bytes
```
- 低于阈值 → 降级到冷存（离线、可逆）；
- **永不遗忘两类**：`constraints` 与 `kind`/`is_a` 骨架；`source=master` 的纠正。

**硬预算**：活跃集设字节上限；**加一条必须删或合并一条**。这是逼泛化、防堆积的唯一可靠机制。

---

## 9. 展开（算力控制）

- 每次推理有 **expansion budget**（节点数上限）。
- **展开必须由"当前正在检查的那条约束"驱动**，不是由遍历驱动。
- 默认在**名字层**推理；只有约束被违反时才展开。

---

## 10. v0 范围（明确不做什么）

**做**：节点/边存储、kind + is_a、显式槽、约束挂载、出处、复用计数、规范形去重、硬预算、冷存降级。

**不做**：自动类型推断、自动合并、自由自然语言输入、嵌入/相似度（那是 §15 的事，v1）、任何神经部件、任何 LLM。

---

## 11. v0 的种子来源（按价值排序）

1. **代码库**——已验证、可执行、带类型的结构库。程序就是结晶化的推理，且天然满足可实例化测试（换参数仍成立）。
2. **本机环境事实**——路径、端口、模型、实测数字。**完全接地，当场可验证**，是最便宜的起点。
3. **结构化导入**——schema、配置文件、数据库模式。
4. **主人的纠正**——量最小、每字节最值钱。

**禁止**：先设计通用本体（Cyc 死因）。本体从导入和经验里长。

---

## 12. 验收（v0 完成的定义）

不是"能存能查"，而是这三条可测：

1. 同一课的不同措辞 → **规范形哈希相同**（同构重复率 ≈ 0）；
2. 加一条新条目时，**必须**给出删/合并对象（硬预算生效）；
3. 一条 `proposed` 条目**无法**参与硬约束判定（出处隔离生效）。
