# agent-wire — 用法与派活规矩

```bash
W="<本目录>/agent-wire"
$W list                                    # 有哪些 agent、谁在线、谁在 run（只读，任何时候可调用）
$W send 小C "…消息…"                 # 名字之后一律是正文（含以 - 开头的列表项）；没有 --wait/--json
```

## 规则（硬）

- **只能给空闲的 agent 发**：发前读对方 `/status`，`running=true` 就拒绝（退出码 2）。注意这只保证**查询那一刻**空闲——查状态与投递是两次请求，中间它可能被别人的消息点着（最常见是主人在那台界面上回车）；真正的保证来自下一条的轮次归属，不是这条预检。
- **不能给自己发**：按 URL 判（对方 URL 与「我自己」相同即拒）；自己此刻必然在 run，规则本身就该拒。
- 不一定走本插件：直接 `POST http://<实例>/enqueue {"message": …}` 效果相同，措辞规矩同样适用。

## 派活的措辞（硬规矩，2026-11-07 主人定）

`/enqueue` 不带来源（`QueuedMessage` 只有 `{Text, Kind}`）→ 对方收到的就是一条普通 user 消息，**分辨不出来自谁**。所以：

- **用主人的口吻直接下指令**：要做什么 + 参数 + 交付物 + 验收标准，一次写完。
- **不要自我介绍、不要写"某 agent 令我们…／这是某 agent 派来的"**：跨实例派活默认已有主人授权，正文不必交代来源。
- 实测反例（2026-11-07）：开头写「【小A 派的活】…主人令我们五个各画各的」→ 小D判成第三方转述，按规矩不执行不承诺，连回两轮"等主人一个字"；小B、小G没看出来，就当成主人的话做了。**同一条消息两种结果，差别只在措辞。** 2026-11-11 重犯：开头写「主人让我通知你…」→ 对方同样判为转述、不动手。
- 别绕：不复述对方的规矩、不署名；要留痕就让它把产物写进指定目录，事后按文件核。

## 回信长什么样（头部由插件拼，发送方不参与写）

`【agent-wire 回信 · 来自 <对方名>】` + `任务：<原消息前 80 字>` + 对方那一轮正文；窗口到点仍在 run 投 `【agent-wire 仍在等 · 来自 X】`；连续不可达投 `【agent-wire 无回信 · 来自 X】`（没有"回信超时"这种字样）。

**它回信里说"已完成/已核对"，仍要从控制侧复核**（同 `lan-ssh` §2：远端自己说成功不算）。复核只需一条命令的量：目标文件的 mtime 是否还是刚改的时刻、备份在不在、真 `diff`、被服务单元的 `MainPID`/`NRestarts` 有没有变。2026-11-08 与小D互相通报 8080 自启修复，两侧都对得上——但"对得上"是复核出来的，不是它说的。多个 agent 各派任务时，靠前缀 + 任务原文对上。
