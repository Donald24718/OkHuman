# cron — 链路、语义与解耦契约

给 OkHuman 实例排定时任务的**独立常驻进程**（Go 单文件 `main.go`，标准库无第三方依赖）：到点把任务 prompt 通过 `POST /enqueue` 投进该实例的消息队列，**只管发、不等那一轮跑完**（2026-10-22 改）。插件拿到入队位置就返回；要看结果去实例自己的界面看。每个实例独立维护自己的 CronStore，与主程序零代码耦合。

## 链路

- 调度循环 `tick_ms`（默认 1000ms）扫各实例 store，`next_run_at` 到期 → 触发
- 触发 = `POST {实例url}/enqueue { message: <prompt> }`，返回 `{position}` 即结束。入队是瞬时动作，HTTP 超时固定 10s（只防实例整个 HTTP 层卡死，**不是**等它跑完）
- **为什么不等**：旧的 `/chat` 同步等整轮带来三个坑——① 插件 goroutine 自旋挂到 600s、同实例其它任务被串行化；② "超时但其实跑了"的误判（run 绑 `context.Background()`，客户端断开不会取消那一轮，插件却已记成失败）；③ 等待窗口=整个 run，期间点的"暂停"会被跑完时的重排抹掉。只管发把这三条一起去掉了
- **代价**：插件拿不到 reply。`recent_runs` 里记的是入队位置，不是回复字数
- **重启补跑**：启动时 `rescheduleOnBoot` 检测错过的周期，`missed` 个只补 1 次，补跑次数上限 `catchup_max`（默认 3）；单次任务（`at`）过期同样补跑一次
- 多实例：`instances[]` 每项 `{ id, url }`，id 不可重复；任务按 `?inst=<id>` 分仓

## 解耦契约（改代码前自检）

- [x] 独立进程、独立二进制，不 import 任何 OkHuman 模块
- [x] 与主进程只有一条线：`POST {实例}/enqueue`（主程序的同步 /chat 已于 2026-11-12 删除）
- [x] 数据全在本目录 `data/`
- [x] 挂掉只断定时任务，主进程与其他插件不受影响
