# plugins/ — 插件与技能仓管理规范（RULE）

本目录 = OkHuman 的插件与技能容器，与主程序完全解耦。插件**扁平**平铺在本目录；技能库在 `skills/`，**日期层级**。

## 布局与必备文件

| 位置 | 布局 |
|---|---|
| `plugins/<插件>/` | 扁平，不分层 |
| `plugins/skills/year_<年>/month_<月>/day_<日>/<skill>/` | 日期层级，只放 skill |

日期层级：按**当天**日期进入——day 目录已存在就直接放，不存在才逐级新建；同一天创建的多个条目共用同一 day 目录。day 目录内的 `README.md` = 当天进什么写一行的人工索引。
- **文档里的本机事实用占位符，不写真实机器身份**：挂载路径写 `<本地盘>/<模型盘>/<另一台盘>/<数据盘>`，数据目录写 `$OKHUMAN_DATA_DIR`，跳板机写 `<跳板机 IP>`，账户写 `<用户>`；实例昵称统一 `小A`/`小B`…（与 `voice-chat` 的唤醒词配置一致）。

- **插件**：`README.md`（启动 + 配置 + 排障）+ `meta.json`
- **skill**：`SKILL.md`（**本机实测验证过**的经验，带日期，照它执行）+ 可选 `scripts/`、`references/` + `meta.json`
- **`meta.json` = scout 的唯一索引信号；索引只由 name / keywords / summary / 路径构成，正文不进索引。** `summary` 必填且 **≤400 字符**：只写「这是什么 + 何时用它 + 子模块/子技能叫什么、在哪」——`/search` 一次返回 10 条、每条都带 summary 进上下文，长摘要就是拿上下文换不到用的东西。`keywords` 必填，**只放本条目独有信号**（端点/端口、模型与文件名、节点名与命令名、报错原文、别名、现象原文词：弹窗文案、验证提示语）；**禁止通用词**（「时间轴」「显存不够」「画面不动」「选卡」）——加了等于把这些查询从整库抢走。`name` 可选（缺省用目录名）。**没写 keywords ≈ 该条目在口语查询下不存在。**
- **改 `meta.json` 前先打印现有字段与类型**：`keywords` 可能是字符串或数组；对字符串做 `set()` 会拆成单字、毁掉该条关键词。
- **凭据与 API key 只落本地、只给自己用**：需要它的条目就直接记（如 `credentials` 这类 skill），别每次去别处找；对外一律不引用、不粘贴、不复述来源。外泄的判据在 `prompts/03-channel-safety.md`，不靠把凭据藏起来。
- **vendored 第三方内容不改写、不压缩**（如 `MiniMax-H3-Skills/` 及其 `.cn`），只在母文档路由表里点名。

## skill 怎么写

- **建前先查重**（先搜索引 + `find skills -name SKILL.md`）：命中同域（同一网站/工具/能力面）就**并入既有 skill 加小节，不新建平行 skill**。
- 一个条目覆盖多件事时，母文档（插件 `README.md` 与 skill 的 `SKILL.md` 同一套）**只写路由 + 共用前置**（登录态、通用事实、脚本索引），并**点名每个子文档**（scout 不索引它们）；`summary` 只写到子文档名 + 它管什么。划分判据：同一能力面的不同任务 → 子文档；不同能力面 → 另建条目（仍先查重）。共用内容只留一处，引用写「§N 在 `../SKILL.md`」。
- 路由做**两栏**：`要做什么 → 文件`，和 **`遇到什么现象 → 文件`**（报错原文、弹窗文案、「正文为空」「只有骨架屏」这类）——只在认出自己的症状时才会跳转，现象栏是入口。
- **硬判据：母文档不得出现参数、端口、完整命令、实测数字——出现数字即违规**；数字与坑属于子文档；**坑集中在条目级 `trouble.md` 也算**（前提：母文档的现象栏指到它），此时其余子文档不必各自再挂一段。
- **只许一层**：母文档 → 叶子文档。**不建分组文件夹、不做二级路由**——多一跳就多半不去跳，嵌套只会放大「我以为手头这段够用」。**叶子数与母文档行数都不设上限**：数量不是划分依据，只按能力面与症状划（不同能力面 → 另建条目，条目层才是能被 `/search` 命中的层）。叶子之间**可以**互相指路：判据是这条引用必须带来本段没有的可执行信息，本地已把结论说完的不得再挂「见 X」。
- 环境变了（换模型、服务重建、端点变化）→ 同步改 SKILL.md 里的「环境事实」。

## scout 索引判据（插件与技能同一套）

- 递归扫 `plugin_root`：任意深度含非空 `summary` 的 `meta.json` 的目录 → 入索引。分类容器/日期目录不入库；运行时资产目录（`venv`、`data` 等）剪枝，**但该目录自己带 `meta.json` 就不剪**。「搜不到」的第一原因是没有 `meta.json`。
- **纯关键词检索，没有语义向量；索引只在内存、不落盘**（真源就是 `meta.json`，启动即扫毫秒级）。实测数据与规模阈值只写在 `scout/README.md`。
- 改完 README / meta.json → `curl -X POST http://127.0.0.1:8480/reindex`。
- **搜不到先 `GET /doctor` 再下结论**：它报 `no_keywords / stale_in_index / missing_from_index / same_name / meta_problems`；`/health` 的 `docs=0` = 服务没起或数据盘没挂载。
- **同名不自动取舍**：都返回 + `same_name` 计数，由调用方决定删哪份。发现 README / meta 过时 → 就地修正。

### keywords 的边界（怎么写、怎么不破坏别人的召回）

1. 通用词只归提供该能力面的条目（显卡/显存 → 监控，截图 → 看屏幕）；场景条目不得持通用词。
2. 窄条目只用场景专名：别名与主机名/IP、端口端点、命令与文件名、节点名、报错原文、现象原文词。
3. 要口语召回就用限定形式（`抖音回评论`、`机器闲不闲`），不裸拿通用词。
4. 方向与边界写进 `summary`（asr「音频→文字」/ tts「文字→声音」），不靠加词；也不要把本条目的子命令、功能短语塞进 keywords——那是把正文搬进信号层。

改词后必做：逐个新词 `/search`，第一名不是自己就不收；扫各 `meta.json` 的 `keywords` 求交集，交集即抢词；再试几个相邻条目的老查询，确认它们还在前排。**别为刷分调词。**

## 写作纪律：任何文件都要精简，只记录可复用的东西

适用**一切写出来的东西**（代码与注释、SKILL.md 与子模块、README、`meta.json`、LESSONS、方案稿、归档说明）。唯一判据是**可复用**：能被下次直接照做的才写——结论、参数与上限、入口与端点、坐标、判据、失败的真因与绕法、能当阈值的实测数（标日期）、插件/CLI 的完整命令与参数参考；出现即删：叙事与过程（「先…然后…」「结果发现」）、决策心路与感想、只对本次成立的细节、别处已写过的话（重复只留一处，其余写「见 X」）。
**改 = 先读原文再动笔**：任何改动（代码、`config.json`、任何文本文件、跨机/跨树复制）都必须先读被改对象的原文、与原文逐处对比差异（必要时 `diff`）再落笔，**禁止不读原文直接覆盖**——整文件写回、`cp`/`rsync`/`tar` 跨机覆盖都算。
**同一事实只有一处**（路径根、模型位置、端口、验收数字这类）；出现第二处即缺陷 → 删成「见 X」。**过时的旧长文**加头部横幅标**归档**（写明以 X 为准，冲突以 X 为准），不与现行文件混读。
新增是最后手段：先找这条事实该落在哪一处已有位置，确认没有落点才新建；**同一次编辑不得净增行**（加几行就在同一次删掉等量重复或过时内容）。写完自查：**删掉它下次会不会走弯路？不会 → 删。**

## 解耦契约（所有新插件必须遵守）

1. **不 import OkHuman 任何模块**，不依赖源码树任何文件。
2. **不共享进程/内存**：插件是独立进程，只走公开 HTTP —— `POST /enqueue`（异步）+ `GET /events`（SSE）或 `GET /events/poll`（短轮询）。同步的 `POST /chat` 已于 2026-11-12 删除（无调用方），旧的 `POST /chat/stream` 更早已删（慢客户端会把实例卡死）；要流式就走 `/enqueue` + `/events`。
3. **配置自管**：`config.json` 放插件目录内，不进 OkHuman 的 `config/`；敏感值只落插件自己的文件。
4. **数据自管**：运行时数据放 `<插件>/data/`。
5. **独立可跑**：每个插件 = 独立 Go 模块（含 `go.mod`）+ 独立 git 仓，`cd <插件目录> && go build ./...` 可单独编译；无外网用 `GOPROXY=off GOSUMDB=off`。二进制、`data/`、含密钥的 `config.json` 不入 git（配置样例写 `config.json.example`）。

## 多实例与构建

- 一个进程 = 一个 agent：插件配置用 `instances[]` 列 `{id, url}` 并按 url 路由（`qq-channel` 用 `bots[].instance`；`cron` 每实例独立存储）。
- 各插件单独编译：`cd <插件目录> && go build -o <二进制名> .`。**改完源码 = 没干活；重编 + 真实启动验证 = 才干完。**
