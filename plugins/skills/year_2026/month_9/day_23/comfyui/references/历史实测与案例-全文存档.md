## 通用 API 流程（所有任务都走这套）

**提交** → **查进度** → **收输出**，三步。

```python
import json, urllib.request

# 1. 提交：graph 是 {node_id: {"class_type": ..., "inputs": {...}}}
#    inputs 里引用别的节点输出写 ["node_id", 0]（第0个输出）
req = urllib.request.Request(
    "http://127.0.0.1:8188/prompt",
    data=json.dumps({"prompt": graph, "client_id": "my_task"}).encode(),
    headers={"Content-Type": "application/json"})
out = json.loads(urllib.request.urlopen(req).read())
pid = out["prompt_id"]
# out["node_errors"] 非空 = 校验失败，看具体哪个节点缺什么参数

# 2. 查进度
json.loads(urllib.request.urlopen(f"http://127.0.0.1:8188/history/{pid}").read())
json.loads(urllib.request.urlopen("http://127.0.0.1:8188/queue").read())  # queue_running / queue_pending

# 3. 收输出
# history[pid]["outputs"][node_id]["videos" | "images"] → [{"filename", "subfolder", "type"}]
# 完整路径 = <本地盘>/ComfyUI-0.37.0/output/[subfolder/]filename
```

**看图质检**：要亲眼看出图（角色脸/服装/构图是否达标）用看图插件 `plugins/view_image/okattach <输出文件> --note "说明"`，图直接进自己视觉上下文；不要调别的多模态模型描述图片（有损）。
```

其他有用端点：
- `GET /object_info` — 全部节点定义（`required`/`optional` 输入、输出类型）。**不确定节点签名就查它，别猜。**
- `GET /object_info/<NodeName>` — 单节点详情。
- `GET /system_stats` — 模型加载状态、显存。
- `POST /interrupt` — 中断当前任务；`POST /queue/{delete,clear}`。

**⚠️ 判断"任务失败"的坑**：队列变空 ≠ 失败。完成时 history 落盘有几秒延迟，失败时队列也空。
正确姿势（见 `scripts/submit_video_chain_reference.py` 的 `wait_files`）：轮询 `history/{pid}` 找输出文件；队列空了先宽限 90s 再判定失败。

**⚠️ 大输出轮询别用 sleep 阻塞**：视频一集要 30min+，轮询脚本放后台跑（OkHuman 的 bash 工具 30s 未完成自动转后台；长驻脚本用 setsid 脱离），或者用 cron 定时任务盯。

## 视频：MiniMax H3 R2V / I2V（已验证管线）

生成带**原生音轨**（台词+音效，无 BGM）的视频。完整可运行参考：`scripts/submit_video_chain_reference.py`（坦克大战 v2 五集链式 I2V，真实跑通）。

### 节点管线（API 格式）

```
UNETLoader(minimax_h3_ref2va_pruned_bf16.safetensors)           → MODEL   # R2V 用 ref2va；T2V/I2V 用 minimax_h3_fl2va_pruned_bf16（weight_dtype="default" 即按 bf16 原精度跑）
CLIPLoader(qwen3-vl-32b-minimax-h3-fp8-comfyui.safetensors, type="minimax") → CLIP
VAELoader(minimax_h3_video_vae_fp16.safetensors)                → 视频VAE
VAELoader(minimax_h3_audio_vae_fp32.safetensors)                → 音频VAE

LoadImage(图片文件名)                                            → 首帧/参考图（只认 input 目录的文件名）

# R2V：三视图/参考图 → 视频（EP1 用这个建立角色）
MiniMaxH3ReferenceToVideo(clip, vae, audio_vae, prompt, width, height, length,
                          ref_image_size="match", ref_images={"ref_image_0": [image_node, 0]})
# 输出: [0]=CONDITIONING, [1]=LATENT

# I2V：首帧 → 视频（后续集用上一集尾帧，实现一镜到底）
MiniMaxH3ImageToVideo(clip, vae, prompt, width, height, length, first_frame=[image_node, 0])
# 输出: [0]=CONDITIONING, [1]=LATENT   （⚠️ I2V 没有 audio_vae 输入！）

BasicGuider(model, conditioning=[cond_node, 0])
KSamplerSelect(sampler_name="res_multistep")
BasicScheduler(model, scheduler="normal", steps=20, denoise=1.0)
RandomNoise(noise_seed=SEED)
SamplerCustomAdvanced(noise, guider, sampler, sigmas, latent_image=[cond_node, 1])  # LATENT 取 [1]！
VAEDecode(samples, vae=视频VAE)      → 帧
VAEDecodeAudio(samples, vae=音频VAE) → 音频
CreateVideo(images, audio, fps=24, bit_depth=8)
SaveVideo(video, filename_prefix="mytask/ep1", format="mp4", codec="auto")  # codec 必填！
```

### 关键参数

- `length` = **帧数**不是秒数。24fps 下：277帧 ≈ 11.5s（长序列，~140s/步）；124帧 ≈ 5.2s（短钩子）。
- 分辨率：**官方 megapixels 档位表（16:9）**，节点 width/height step=32，直接照表取值：

  | MP | 输出 | | MP | 输出 |
  |---|---|---|---|---|
  | 0.2 | 608×352 | | 0.9 | 1280×736 |
  | 0.3 | 736×416 | | 0.98 | 1344×768（节点默认） |
  | 0.4 | 864×480 | | 1.0 | 1376×768 |
  | 0.5 | 960×544 | | 1.2 | 1504×832 |
  | 0.6 | 1056×608 | | 1.5 | 1664×928 |
  | 0.7 | 1152×640 | | 1.8 | 1824×1024 |
  | 0.8 | 1216×672 | | 2.0 | 1920×1088 |

  表源：`custom_nodes/Comfyui_Minimax_h3_latent_Upscaler/workflow_templates/` 里的 Size Settings Reference 注记（2026-09-17 抄录）。
  **非官方扩展**：2560×1440（≈3.7MP）22 帧短序列实测可用、不 OOM（四视图标准，见下节）；360 帧长视频 960×1280 会 OOM。
- steps=20，sampler `res_multistep`，scheduler `normal`，seed 固定可复现。
- **4060 Ti 上实测速度**：短序列 ~37s/步，长序列 ~140s/步，一集约 30min。

### Prompt 写法（角色一致性 + 台词 + 音效的关键）

H3 是音画同出模型，prompt 里直接写台词和音效描述，它会一起生成。结构（验证有效的模板）：

```
<Subject 1> is the ... (角色外观完整描述，每集 prompt 里原样重复，保证一致性)

summary: 一句话剧情概要

detailed_description: 2D chibi anime cel-shaded style, ...
(0s-4s) 镜头+动作+台词: "台词原文用引号包起来，注明 in Chinese: "台词""
(4s-8s) ...
(8s-11.5s) ...
Keep the character's face, hairstyle and outfit identical in every frame. No readable text, no watermark.

overall_soundscape: 逐条列音效（键盘声、叮、whoosh…）+ 角色声音描述。Natural sounds only, no background music.

non_diegetic_music: none
```

**铁律**：
- 每集 prompt 都带完整角色描述（模型不跨集记忆）。
- 台词用引号 + `says in Chinese:`，中文原话。
- 想要纯台词无 BGM 就写 `non_diegetic_music: none` + `no background music`（BGM 后期混，见下节）。
- 画面上的文字模型写不准，只写 icon/抽象符号，别指望可读文字。
- **一镜到底主推 = 首尾帧 FLF2V 双锚定（0.37.0，2026-09-29 验证、2026-09-30 v3 复验）**：`MiniMaxH3ImageToVideo` 有可选输入 `last_frame`——首帧/尾帧都严格贴合给定关键帧，段间天然无缝，关键帧完全可控、接缝零漂移。分镜流程：① 用图像模型（Qwen-Image-2.1 编辑模式）以同一 16:9 底图为参考生成 N 张 beat 静帧（每张只改姿势，身份/服装/背景/光照锁定）；② N-1 段 I2V，seg_i = first:beat_i + last:beat_{i+1}；③ ffmpeg `xfade` 100ms 交叉淡化拼接（配套 `acrossfade`，见踩坑 19）。⚠️ **双锚定≠自动出动作**：若提示词设计纯静段落或只描述端点状态，模型走"最短路径"近似插值，画面像 PPT/幻灯片（2026-09-30 v1 实锤）。正确写法=提示词**全程无静段落、逐秒写动作弧+明确运动机制**（什么在动、怎么动、何时到位），beat 端点姿势差要大。此写法下四段全部走出真实动作路径（中间帧可见手在途中、头渐倾、红晕渐起），PPT 感消除。**2026-09-30 v5 复验推翻上一条**：时间戳状态式提示词（"(0s-2s)状态A (2s-4s)状态B"）实测反而把双锚定段变成**hold-jump-hold**（端着起点→1-2s 一次瞬移→端着终点，seg23 出现单帧灰阶差 29 的 teleport），因为时间戳状态对模型=关键帧清单。正解=**单一连续物理过程**提示词：不写时间戳状态，只写"整个镜头一个不间断的渐进动作，每秒比前一秒多一点进度，无停顿无瞬移"+负面 no sudden jump/teleport/freeze。另两条硬规矩：**① 段长按动作幅度设计，禁止等长**（小动作 5.2s / 细腻小动作 6.7s / 中等前倾 8.3s / 大位移跨坐 10s，length=帧数：124/160/200/240 @24fps）；**② 验收必须用逐帧运动能量曲线**（相邻帧灰阶均值差按 0.5s 分桶）：单帧差 >12=瞬移、连续 >1.5s 差 <0.3=死静段，两者出现即打回换 seed 重跑。抽 5 帧看图验收会漏掉 1s 瞬移（2026-09-30 实锤误判通过）。**2026-09-30 v6/v7 终审修正**：按"大位移拆小位移子段+mid 过渡关键帧"路线走，mid 关键帧本身会退化（H3 把"躺姿抬臂"重构为坐姿，beat2→mid23 在 80/124 帧、两种提示词风格下全部瞬移，见踩坑 23）——**子段拆分不是通用解**。分动作类型处理：① 全身大位移（前倾/跨坐级，34/45）：单段 200/240 帧 + 单一连续过程提示词直接 PASS（峰值帧差 ≤8.8、覆盖 61-81%）；② 手指级小位移（拇指入嘴，23）：双锚定单段 160 帧无瞬移但动作被压缩到 ~1s，**解法=帧手术**——裁出动作窗口（ffmpeg -ss 起点 -t 窗长 重编码），把段长压到动作幅度（7.3s→4.8s），无瞬移的平滑滑动直接可用。最终 v7 成片 28.5s 整片能量曲线 PASS（峰值 8.7/死静 ≤2.5s/覆盖 61%）+ 5 检查点（首帧/3 接缝/末帧）视觉连续，发 QQ。**用户仍报"瞬移"（2026-09-30 下午 v8 修正）**：逐帧差分析定位到 45 段内两个**连续但快速的物理事件**（髋部落胸 0.4s、手臂绕颈 0.5s，单帧差 7-9.2，前后帧也 3-5）——不是孤立瞬移（前后帧近 0），但"静-爆发-静"节奏在人眼看来仍像跳。提示词没写停顿，是模型把动作分布在快事件里；**"slow even pace"提示词能改善分布（v2 覆盖 86%、无长死静）但压不掉物理上就快的动作**。解法=同提示词**换 seed 重抽对比**（seed 7→42，v3 快事件更少：单点 9.6 vs 10.8、绕颈 1.2s vs 0.7s），取更平的版本重拼重发。教训：**逐帧运动能量曲线（0.5s 分桶）会漏掉"连续快速事件"，验收必须加逐帧差 top-N 分析 + 尖峰时刻抽帧看图**；孤立尖峰（单帧>8 且前后帧<2）=真瞬移必重跑，连续快帧（10 帧都 7+）=真实物理动作可接受。
- **链式首帧 I2V（备选，无尾帧/端点姿势差小/不需精确落点时用）**：下一段 I2V 的首帧取上一段**真实尾帧**（`ffmpeg -sseof -0.25 -i in.mp4 -frames:v 1 -update 1 out.png`，png 放到 `input/` 目录），段间零跳变。
- **beat 静帧机位必须锁死**：编辑模型可能在不同 beat 间翻转左右构图（实测 5 张里 1 张翻了）——prompt 里写明 "SAME CAMERA AS <image1>: 男头在画面左侧/她在右侧"，出图后逐张 QC 机位，翻了就换 seed 重跑（seed7 翻、seed42+机位锁过）。机位翻转的段会生成镜像滑动，一镜到底就废了。
- **beat 图要先拷进 `input/`**：LoadImage 只认 input 目录（output 里的路径直接 400 "Invalid image file"）。

## 角色四视图设定图（T2V 短序列，2026-09-17 验证）

文字生成角色设定 sheet（H3 T2V 管线 + 22 帧短序列 + 抽首帧）。小说项目角色设定图标准。

### 布局标准（四视图·无头二视图）

16:9 画布，4 个冻结面板：
1. **VIEW 1 正脸大半身像（带头）**——左半（x=0-45%），waist-up 半身，头约占面板高 1/3，头顶 ≥15% 留白（防裁头）
2. **VIEW 2 正面全身（去头）**——在领口处精确裁切，无头无脸无脖颈残段
3. **VIEW 3 侧 90° 全身（去头）**——同样领口裁切
4. **VIEW 4 背面全身（带头）**——只见后脑与头发，无任何五官

**为什么 2/3 去头**：H3 T2V 会把多脸 sheet 里的正/侧脸"脑补"成别的脸（与正脸漂移）；去头后画面里唯一的脸 = 正脸肖像 + 后脑（无五官），漂移风险消除。

## 混音：BGM 进成片（不盖过台词）

**原则：人声/台词轨不动，BGM 垫底 + 台词侧链让位。** 成片响度必须和加 BGM 前基本一致（±0.5dB）。

已验证配方（坦克大战 v2 成片，57.8s）：

```bash
# BGM 压 -8dB 垫底 + sidechaincompress 以台词轨做侧链（台词一响 BGM 让 5:1）
ffmpeg -i 成片.mp4 -i bgm.mp3 -filter_complex "
  [1:a]atrim=0:DUR,asetpts=PTS-STARTPTS,volume=-8dB[bgmv];
  [bgmv][0:a]sidechaincompress=threshold=0.04:ratio=5:attack=5:release=350:makeup=1.0:level_sc=1.0[bgmsc];
  [0:a]volume=-1dB[dlg];
  [dlg][bgmsc]amix=inputs=2:normalize=0:duration=first,alimiter=limit=0.95[mix]" \
  -map 0:v -map "[mix]" -c:v copy -c:a aac -b:a 192k 成片_bgm.mp4
```

- `-c:v copy` 视频流无损复制，只重混音频。
- BGM 比台词低 ≥9dB 是安全区（台词 mean -15.8dB 时 BGM 垫到 -25dB 左右）。
- 验证：`ffmpeg -i out.mp4 -af volumedetect -f null - 2>&1 | grep volume`，成片 mean 应≈原片 mean。
- BGM 时长 > 成片就 atrim 截齐；想淡出加 `afade=t=out:st=...:d=...`。

## 音乐生成实测补充（2026-10-05，女声 chill 后摇+hiphop 141s）

- **钉卡必须加 `CUDA_DEVICE_ORDER=PCI_BUS_ID`**：本机 CUDA 枚举顺序 ≠ nvidia-smi index。
  只给 `CUDA_VISIBLE_DEVICES=2` 会落到物理 3 号卡（已被别的模型占 15.7G），文本编码节点直接
  `RuntimeError: VRAM grow failed`。正确：`CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=2`，
  起完用 `nvidia-smi --query-compute-apps=gpu_uuid,pid,used_memory` 核对 uuid 对上空闲卡。
- **150 秒的歌在单张 V100 上很慢**：AR sampling 3751 步 ≈ 30 分钟；之后 VAE 解码会
  `OOM ... retrying with tiled VAE decoding`（文本编码器 8.7G + DiT 常驻，剩不下 4.8G），
  分块解码能出但更慢。**总耗时 ~32 分钟**，别按"64s 曲几分钟"外推。
- **盯 history 时注意 SaveAudioMP3 的输出键**：轮询脚本找 `outputs[*]["audios"]` 可能一直不命中，
  直接看 `output/audio/<prefix>_00001.mp3` 落盘更可靠。
- **发 QQ 有 4.5MB 上限**（qq-channel 桥）：320k MP3 141s ≈ 5.4MB 会被反复拒发（日志刷
  `文件超 4.5MB 上限未发`）。`ffmpeg -c:a libmp3lame -b:a 160k` → 2.8MB 即可，原片留盘。

## 踩坑清单（全部真实踩过）

1. **`SaveVideo` 必须给 `codec`**（如 `"auto"`），不给会在采样全跑完后崩溃，白跑 30min/集。

20. **H3 FLF2V 大位移段会 hold-jump-hold（2026-09-30 实测）**：双锚定+大姿势差（抬腿跨坐级）时，flow-matching 走最省力路径=端起点+短时爆发+端终点，画面表现为关键帧跳转。缓解组合拳：段长给足（大位移 10s）+ 单一连续过程提示词（禁时间戳状态清单）+ 逐帧运动能量曲线验收 + 不过关换 seed。小位移段（抬手级）不受此影响。**v6 复验（2026-09-30）**：大位移缓解组合拳对 34（200 帧）/45（240 帧）实测有效（PASS）；但手指级小位移（23，拇指入嘴）160/240 帧+连续过程提示词仍把动作压缩进 1-1.5s（无瞬移、hold-slide-hold），且拆子段+mid 关键帧失败（mid 姿势退化，踩坑 23）——小位移段用"单段 160 帧+帧手术裁窗口"（见一镜到底节）。
19. **多段 xfade 拼接必须配套 acrossfade（2026-09-30 实测）**：ffmpeg `xfade` 只淡画面，音轨不同步淡化会出现"画面淡出时声音还在"的音画错位。写法：`[0:a][1:a]acrossfade=d=0.1[a01]; [a01][2:a]acrossfade=d=0.1[...]` 链式接下去，与 xfade 的 duration 一致。xfade 的 offset=前段累计时长-0.1（5.167s 段：5.067/10.134/15.201），4 段 20.44s 成片 2.9MB 可直接发 QQ。
22. **H3 `length` 填充不稳**（2026-09-30 实测）：MiniMaxH3ImageToVideo 的 length 是下限，实际输出帧数 124→124、160→175、200→209、240→243，无规律。拼接时 xfade offset **必须用 ffprobe 实测各段时长**累加，别按 length 算。
25. **xfade 交叉淡化接缝会制造"虚影"（2026-09-30 v8→v9 用户实测反馈）**：多段一镜到底拼接用 xfade(0.1s) 过渡时，若接缝两侧的锚点帧不是同一帧（如一段的末帧=精确 beat2，另一段首帧=beat2+2.5s 漂移，差 5.35），混帧窗（2-3 帧）会把两个错位的 pose 叠成柔化重影——用户报"前面有虚影"。缩略图看不出，必须**接缝 ±0.2s 逐帧 + 面部区域 2x 放大 crop** 才能看到。修复=接缝两侧帧近似时**视频硬切**（concat filter，零混帧；锚点漂移 5.35 的硬切人眼读不出），**音频保留 acrossfade 0.1s** 防切割爆音，apad/atrim 把音频补齐到视频时长。锚点精确同帧的接缝硬切=像素级无缝。xfade 只适合两侧帧差异大、需要平滑过渡的场合。
24. **FLF2V 连续动作段也有"快事件"问题（2026-09-30 v8 实测）**：大位移段即使提示词写了 slow continuous/slow even pace，模型仍会把物理上就快的动作（落体、手臂绕颈、抬腿）压在 0.3-0.7s 内完成（单帧差 7-10），前后帧也在 3-5——逐帧看是连续运动，但"静-爆发-静"节奏用户感知=瞬移。分桶能量曲线（0.5s）完全看不出（桶均值被摊平）。验收必须：① 逐帧差 top-N 列出（t 时刻+差值）；② 尖峰时刻 ±0.3s 抽帧拼图看是"连续物理动作"还是"孤立跳"；③ 孤立尖峰（单帧>8 且前后帧<2）=重跑；连续快帧=换 seed 重抽取更平版本（同提示词 seed 7 vs 42 实测 10.8→9.6、快事件数 3→1）。
23. **FLF2V 的 mid 过渡关键帧会姿势退化（2026-09-30 实测）**：用 Qwen-Image-2.1 生成的中间姿势图（躺姿抬臂托脸、拇指贴下唇）作 last_frame 时，H3 反复把该姿势重构为"男坐起"（beat2→mid23 在 80f/124f、时间戳/连续过程两种提示词下全部单帧瞬移 41+，末帧≠锚点）。抬臂躺姿的三角形手臂轮廓与坐姿歧义太大。mid 关键帧若要用，必须选姿势歧义小的（如坐姿/站姿的中间位），躺姿+抬臂慎用；手指级小位移过渡别依赖 mid 拆分（见踩坑 20 补充）。（注：所用 Qwen-Image-2.1 已于 2026-10-06 删除）

## 工作流习惯（多集/长任务）

- **链式驱动脚本**：EP1 R2V 建角色 → 抽尾帧 → EP2..N 逐集 I2V，每集完成后才提交下一集；已完成的集按输出文件存在性 SKIP（支持中断续跑）。参考 `scripts/submit_video_chain_reference.py` 的 main()。
- 长任务（>1h）用 cron 定时任务轮询进度 + 自动收尾（拼片/发审/删任务），别傻等。
- 成片拼接：各集 mp4 直接 `concat`（同分辨率同编码）；台词是各集自带的，BGM 最后一次性混（见上节）。
- 交付：原片 + `_6m` 审片版 + 分集，一起发；文案/字幕文件放 `$OKHUMAN_DATA_DIR`。

## H3 REF2I 生图 + 纯定格 MV（2026-10-05 全流程实测，本机模型名与旧文档不同）

**本机真实模型名**（`/object_info/UNETLoader` 实测，旧文档里的名字不存在）：
- UNET：`minimax_h3_ref2va_pruned_bf16.safetensors`（参考图生图/生视频）、`minimax_h3_fl2va_pruned_bf16.safetensors`（首尾帧生视频）。**Hybrid-int8 那个符号链接是坏的**，别用。
- 文本编码器：`qwen3-vl-32b-minimax-h3-fp8-comfyui.safetensors`，`CLIPLoader type="minimax"`（26.5G，会自动 offload 到内存）
- VAE：视频 `minimax_h3_video_vae_fp16`，音频 `minimax_h3_audio_vae_fp32`（两个 VAELoader，分别接 VAEDecode / VAEDecodeAudio）

**16G V100 上跑 40G bf16 的唯一可行法**：`UNETLoader weight_dtype="fp8_e4m3fn"` + 分辨率降一档。
`MiniMaxH3ImageToVideo` 124帧 @1280×704 会 `VRAM grow failed: 616MB`；改 **fp8 + 1024×576** 才挤进去（15.9G 常驻，3.5 分/步）。
生图（REF2I）用 **length=5**（17k+5 网格最小档）+ 16 步 ≈ **5.5 分钟/张**；length=22 画质略好但翻倍。

**REF2I 图生图 API 图**（原生节点，零插件）：
`MiniMaxH3ReferenceToVideo(clip,vae,audio_vae,prompt,width,height,length,ref_image_size="match",ref_images.ref_image_0)`
→ out0 接 `BasicGuider(model,conditioning)`；out1(LATENT) 接 `SamplerCustomAdvanced(latent_image)`
+ `BasicScheduler(scheduler="beta",steps=16,denoise=1)` + `KSamplerSelect("res_multistep")` + `RandomNoise`
→ `VAEDecode`(video VAE) → `SaveImage`（length=5 会存 5 张候选帧，取 `_00001_`）。
**没有 negative 输入**，负面只能写进 prompt 文本。

**六段式提示词**（官方语法，`retention_analysis` 是编辑指令核心）：
`subject_definitions`（`<Subject 1>` 绑定 `<Picture 1>` + 逐项列特征）→ `summary`（一句话任务书）
→ `retention_analysis`（`partially preserved — 保留清单 … Replaced: …`，越具体越听话）
→ `detailed_description`（静态镜头 + 构图锚点 + 负面清单）→ `overall_soundscape: N/A` → `non_diegetic_music: N/A`

**身份一致性完胜 Qwen-Image**：H3 会**保住参考图的 2.5 头身 chibi 比例**（Qwen-Image-2.1 会拉成半写实、还会分裂出第二个人/重复灯笼）。
批量出图时把这三条钉死在 `detailed_description`，否则必翻车：
1. `the picture fills the ENTIRE 16:9 frame edge to edge, no black bars, no letterboxing, no pillarboxing`
2. `Exactly one person with exactly two arms and exactly two hands, exactly one paper lantern`
3. `the name tag reads exactly OK` / `no letters on any badge`（否则工牌会写成 `OA`、红环徽章会长出 `BAD!`）

**H3 会补均匀边条**（不是纯黑，是 **RGB(6,10,14)**，均值≈9）：竖向构图时 1280×704 画布里内容只有 664×703（左右各 308px），横向时上下各 90px。
检测别用"均值<6"（会漏），要用**四周有没有结构**：逐行/列 `ImageStat.stddev<1.5 且 mean<16` 判为边条，二分出内容 bbox → 裁掉 → cover 缩放铺满目标分辨率。
（PIL 的 `ImageStat` 取标准差用 `.stddev`，没有 `.variance`。）

**纯定格 MV 配方**（比 H3 生视频省 10 倍时间，141s 成片 22 镜全部出图 ≈ 2 小时，生视频 3 段就要 3.5 小时）：
一句歌词一张图 → 每张图覆盖**它那句歌词的时间区间**（`bounds=[0]+[每句起点]+[总时长]`）
→ 每镜 `zoompan` 慢推近（偶数镜 1.00→1.045、奇数镜反向，片尾 1.04→1.00）
→ 段时长 = 显示时长 + 该段后的 xfade 时长（短句 0.3s、长句 0.5s），xfade offset 用 **ffprobe 实测时长**累加
→ `subtitles=lyrics.ass` 烧字幕 + `vignette=angle=PI/5` + `noise=alls=5:allf=t`（颗粒能盖住不同批次图的画质差）
→ 混原曲 `-shortest`。QQ 投递上限 4.5MB：141s 片 854×470 + `libx264 -preset slow -crf 30` + `aac 96k` ≈ 3.3MB（暗场景压得动）。
