# okattach（attach 插件）

素材注入 OkHuman 上下文：图片（默认原图 native）/ **视频（直通 input_video，按策略编码分段）** / 单帧高清抽取。音频暂不支持（ASR 插件负责）。

## 用法

```
okattach <file>                      图片：原图注入（native，不缩放不压质，默认）
okattach <file> --scaled             图片：压宽 800px / JPEG q2（省 token）
okattach <file> --png                图片：压宽后走 PNG 无损（截图类素材）
okattach video <file> [--seg N]      视频：按策略编码后以 input_video part 注入
okattach video <file> --dry-run      视频：只打印计划（分辨率/分段/token 估算），不编码不 POST
okattach frame <video> <t> [--w W]   视频抽 t 秒单帧，压宽 W（默认 1280）注入为图片
以上均可加 --note "说明"（/attachments 里可见，不进 LLM 上下文）
```

目标端口自动识别：沿**进程父链**找所属 okhuman 主进程，取其 LISTEN 端口（插件由 agent 的 bash 工具启动，父链 okattach←bash←okhuman，端口随实例天然隔离：本机 生产=8451、lil 副本=8452）；脱离 agent 会话跑（父链无 okhuman）时回退 8451 并告警，此时用 `--okhuman-port` 显式指定。

## 视频注入策略（2026-09-20 用户定版）

llama-server 服务端自己抽帧（4fps + 2 帧时序 merge），并**每 5 秒往帧流注入文本时间戳**（`[0m5.00s]` 格式，视频开头有 "Video:"）——时间定位比插件侧抽帧准，模型可答"第几秒发生了什么"（实测误差 ±0.5~1s）。

1. **源宽 < 360px** → 原样注入（不放大不压缩，保清晰）。
2. **源宽 ≥ 360px** → ffmpeg 压到**宽 360px**（360p 档，高按比例取偶）。
3. **每段 ≤ 1 万 tokens**（硬约束）；360p 档单段另加 **≤ 60s** 上限。
4. 超上限自动均分分段；`--seg N` 注入第 N 段。段内时间戳从 0 起，注入文本 part 标注原时间轴范围（如"第 2/4 段：原时间轴 45.0-90.0s"），模型靠它映射回原时间轴。跨段衔接靠各段分别注入（会话里并存）。
5. 估算式 `est_tps = W*H/420`（W/H=目标分辨率；:8080 实测标定，720p 高估 ~13%、320p 基本持平，宁多勿少）。

### 不同分辨率的 token 消耗（:8080 实测，10.03s 视频 prompt_tokens）

| 注入宽度 | 实际分辨率 | prompt_tokens | tokens/秒 | 1 万 tokens 可装时长 |
|---|---|---|---|---|
| 1280 | 1280x612 | 16915 | ~1690 | ~5.9s |
| 720 | 720x358 | 5428 | ~543 | ~18.4s |
| 560 | 560x268 | 3517 | ~352 | ~28.4s |
| 426 | 426x202 | 2026 | ~203 | ~49.2s |
| **360（本插件档）** | 360x178 | ~1530(估算) | ~154 | ~64.8s → 取 60s 档 ≈9.3k |
| 320 | 320x152 | 1165 | ~117 | ~85.4s |

规律：**token ∝ 帧面积（宽度²）**，服务端不缩不放——插件不压宽，1080p 原片每秒 ~2800 tokens，60s 就是 17 万。

### 升级阶梯（清晰度/长度不够时）

- **看不清细节** → `okattach frame <video> <t> --w 1280`：单帧高清（1280 宽 ≈1.1k tokens/帧），模型先定位时间点，再抽该时刻帧确认细节。
- **内容太长** → `--seg N` 分批注入（每段独立一次 okattach 调用；建议按内容主题切段并在 --note 里写段主题）。
- **两者都不够** → 换更长上下文/更大模型的 LLM 端点（插件本身无上限，64MB 文件上限）。

## 依赖与限制

- ffmpeg/ffprobe（本机 6.1.1）；ffprobe 失败（无视频流/非视频）直接退出。
- 文件 ≤ 64MB（与 /inject 侧车上限一致）；注入走 base64，侧车体积 ≈ 文件 ×4/3。
- 视频段编码：libx264 crf23 fast、yuv420p、去音轨（`-ss` 在 `-i` 前 = 快 seek + 帧精确 + 输出时间戳归零）。
- `--note` 只是 /attachments 的展示元数据，**不进 LLM 上下文**；要给模型的时间轴/主题说明写在视频自带的文本 part 或聊天消息里。
- /inject 的 parts 透传支持（任意带 type 的 JSON 对象 part，含 input_video）需 OkHuman 主进程 2026-09-20 版；更早的二进制只认 text/image_url，发视频会 400。
- LLM 端点须支持视频（llama-server MTMD_VIDEO + mmproj）；不支持时 OkHuman 4xx 降级为文本存根自动重试。

## 排障

- 看到 `okattach: 父链未找到 okhuman 主进程，回退默认端口 8451` → 你是在 agent 会话外跑的，属错实例就用 `--okhuman-port` 指定；注入失败 → 看返回状态码：400=主进程旧版或 parts 格式错；0/连接失败=OkHuman 没起。
- 分段数比预期多 → 估算式偏保守（720p 高估 13%），属正常；要精确先看 `--dry-run`。
- 抽帧时间不准 → 确认 ffmpeg ≥5（旧版 -ss 行为不同）。
- 段内时间戳与"原时间轴"对不上 → 模型读的是段内 0 起的时间戳，换算 = 段内时间 + 段起点（注入文本里已写明）。
