# 【归档】视频注入策略（2026-09-20 定版）

**当前后端已不适用**：2026-11-06 实测 `input_video` 不透出（调用返回 ok、侧车写入、估算 ~1.6k tokens，但上下文里没有画面）。本节留作 llama.cpp 后端时代的参考；现行做法 = `okattach frame` 抽帧成图片（判据与成本见 `year_2026/month_11/day_17/video-frames` 技能）。

llama-server 服务端自己抽帧（4fps + 2 帧时序 merge），并**每 5 秒往帧流注入文本时间戳**（`[0m5.00s]` 格式，视频开头有 "Video:"）——时间定位比插件侧抽帧准，模型可答"第几秒发生了什么"（实测误差 ±0.5~1s）。前置条件：LLM 端点须支持视频（llama-server `MTMD_VIDEO` + mmproj），不支持时 OkHuman 收到 4xx 会降级为文本存根自动重试。

1. **源宽 < 360px** → 原样注入（不放大不压缩，保清晰）。
2. **源宽 ≥ 360px** → ffmpeg 压到**宽 360px**（360p 档，高按比例取偶）。
3. **每段 ≤ 1 万 tokens**（硬约束）；360p 档单段另加 **≤ 60s** 上限。
4. 超上限自动均分分段；`--seg N` 注入第 N 段。段内时间戳从 0 起，注入文本 part 标注原时间轴范围（如"第 2/4 段：原时间轴 45.0-90.0s"）。
5. 估算式 `est_tps = W*H/420`（W/H=目标分辨率；:8080 实测标定，720p 高估 ~13%、320p 基本持平，宁多勿少）。

## 不同分辨率的 token 消耗（:8080 实测，10.03s 视频 prompt_tokens）

| 注入宽度 | 实际分辨率 | prompt_tokens | tokens/秒 | 1 万 tokens 可装时长 |
|---|---|---|---|---|
| 1280 | 1280x612 | 16915 | ~1690 | ~5.9s |
| 720 | 720x358 | 5428 | ~543 | ~18.4s |
| 560 | 560x268 | 3517 | ~352 | ~28.4s |
| 426 | 426x202 | 2026 | ~203 | ~49.2s |
| **360（本插件档）** | 360x178 | ~1530(估算) | ~154 | ~64.8s → 取 60s 档 ≈9.3k |
| 320 | 320x152 | 1165 | ~117 | ~85.4s |

规律：**token ∝ 帧面积（宽度²）**，服务端不缩不放——插件不压宽，1080p 原片每秒 ~2800 tokens，60s 就是 17 万。

## 升级阶梯（清晰度/长度不够时）

- **看不清细节** → `okattach frame <video> <t> --w 1280`：单帧高清（1280 宽 ≈1.1k tokens/帧），先定位时间点再抽该时刻帧确认细节。
- **内容太长** → `--seg N` 分批注入（每段独立一次 okattach 调用；按内容主题切段并在 --note 里写段主题）。
- **两者都不够** → 换更长上下文/更大模型的 LLM 端点（插件本身无上限，64MB 文件上限）。
