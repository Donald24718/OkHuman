# `could not find /tmp` —— 根因定位与修复（2026-10-05）

> **结论先行**：
> 1. **`/tmp` 确实会不可用**，不是无害噪音——它是 MSYS 的 `usertemp` 挂载点，
>    挂载目标**由 MSYS 运行时自行推导**，会随宿主会话变化，且**目标目录会被回收**。
> 2. **所有「注入环境变量」的修法全部无效**。实测 `TMP` / `TEMP` / `TMPDIR` / `MSYS_TMP`
>    **都改不动** `/tmp` 的挂载目标（四组控制变量实验，目标纹丝不动）。
> 3. **OkHuman 无法从环境层修**（改不动 MSYS 挂载）。真正有效的修法在**行为层**：
>    通过工具描述让模型别写 `/tmp`，改用 `$TEMP` / 当前目录。

> **本文取代并删除了**同目录下先前的 `bash-tmp告警排查-证伪记录-2026-10-05.md`。
> 那份文档的「证伪」部分**依然成立且被进一步证实**（`TMPDIR` 注入确实无效，见 §2.1），
> 但它的总结论「无需修复、告警无害」**已被推翻**——该结论源于一次「恰好正常」的采样
> （详见 §3.3）。旧文档已删除，避免两份互相矛盾的结论并存；其有效推理已并入本文。

---

## 一、现象

Agent 执行 bash 命令时，stderr 出现：

```
bash.exe: warning: could not find /tmp, please create!
```

伴随命令里的 `/tmp` 写入失败：

```
echo hi > /tmp/x.txt  →  /tmp/x.txt: No such file or directory
```

**时好时坏**——同一条命令，有时成功有时失败。这是本次排查的关键线索。

## 二、被证伪的三条路径

### 2.1 「非 login shell 不读 `/etc/profile` → `TMPDIR` 为空」→ **证伪**

- 依据：`winenv_windows.go` 注释写明「非 login shell（`bash <script>`）不读 /etc/profile」——**这句是真的**。
- 但**推不出**「`/tmp` 不可写」。清理后从全新状态跑非 login bash → `FRESH_OK`。
- 注入 `TMPDIR` 的改动已**全部回滚**（变异测试：注入与否，输出逐字一致）。

### 2.2 「`MSYS_TMP` 未设置导致 `usertemp` 挂载失败」→ **证伪**

对整个 Git 安装目录做二进制字符串扫描：

| 字符串 | 命中位置 |
|---|---|
| `could not find /tmp` / `please create` | **`usr\bin\bash.exe`、`usr\bin\sh.exe`** |
| `usertemp` | `usr\bin\msys-2.0.dll` ✅ |
| `MSYS_TMP` | **0 命中**（整个 Git 目录，ASCII + UTF-16 均无） |

**`MSYS_TMP` 这个变量根本不被任何组件读取**——设它没有任何效果。
另外告警文本位于 **bash 自身**，不在 `msys-2.0.dll`。

### 2.3 「`TEMP` / `TMP` 决定 `/tmp` 挂载目标」→ **证伪**

控制变量实验（用原生进程 python 启动 bash，逐组覆盖环境变量）：

| 组 | 环境变量设置 | `/tmp` 挂载目标 | 写 `/tmp` |
|---|---|---|---|
| A | 不覆盖 | `C:/Users/peli/AppData/Local/Temp` | OK |
| B | `TEMP`+`TMP` 指向自定义目录 | **`.../Temp`（没变）** | OK |
| C | `TEMP`/`TMP`/`TMPDIR` **全部清空** | **`.../Temp`（没变）** | OK |
| D | 设 `MSYS_TMP` | **`.../Temp`（没变）** | OK |

**四组目标完全一致** → `/tmp` 挂载不受这些变量影响。

## 三、真正的根因

### 3.1 `/tmp` 是 MSYS 挂载点，不是普通目录

Git 的 `/etc/fstab`（本机两个 Git 安装**内容一致**）：

```
none / cygdrive binary,posix=0,noacl,user 0 0
none /tmp usertemp binary,posix=0,noacl 0 0
        ^^^^^^^^
```

`usertemp`（位于 `msys-2.0.dll`）让 MSYS 在**启动时**把 `/tmp` 挂载到某个 Windows 目录。

### 3.2 挂载目标会变，且宿主会话目录会被回收

实测观察到同一台机器上 `/tmp` 的挂载目标**有两种形态**：

```
C:/Users/peli/AppData/Local/Temp                              ← 稳定存在
C:/Users/peli/AppData/Local/Temp/reasonix-session-tmp-2119371413   ← 宿主会话临时目录
                                    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^
```

`reasonix-session-tmp-<NNN>` 是**宿主（IDE/宿主进程）为每个会话创建的临时目录，会被回收**。
观察到一次明确因果：

```
mount 指向 .../Temp/reasonix-session-tmp-2119371413
ls -ld 该目录 → No such file or directory     ← 已被回收
echo hi > /tmp/x → WRITE_FAIL                 ← /tmp 必然写失败
```

**根因**：`/tmp` 挂载目标由 MSYS 运行时自行推导（不受环境变量控制），
当它落到**宿主会话临时目录**且该目录已被回收时 → `/tmp` 写操作 ENOENT，
同时 bash 启动早期探测失败，输出 `could not find /tmp, please create!`。

**这就是「时好时坏」的来源**——取决于宿主当时给的是哪一种目录、有没有被回收。

### 3.3 为什么我之前会误判「无需修复」

走 `ExecuteTool` 全链路复现时，**恰好**那一刻 `reasonix-session-tmp-2119371413` 存在
（宿主重建了它）→ 全组 `WRITE_OK` → 我据此下了「告警无害、无需修复」的结论。

**教训：间歇性故障不能凭单次采样下结论。** 必须观察到失败态并锁定其触发条件。

## 四、修复：改在行为层

OkHuman **改不动 MSYS 挂载**（挂载发生在 bash 启动瞬间，OkHuman 只能控制传给它的环境变量，
而环境变量已被证明无效）。唯一可靠的是**让模型不要写 `/tmp`**——用工具描述实现。

### 4.1 实现

新增平台专属 `tmpHint()`（沿用已有的 `detachHint` 分文件模式）：

| 文件 | 实现 |
|---|---|
| `internal/tools/bash_unix.go` | `func tmpHint() string { return "" }` —— Unix 的 `/tmp` 真实可写，无需提示（也守护描述逐字不变） |
| `internal/tools/bash_windows.go` | 返回规避提示，说明改用 `$TEMP` / 当前目录 |
| `internal/tools/config.go` | `buildTools` 的 Description 末尾 `+ tmpHint()` |

Windows 提示文案：

> 临时文件请写到当前目录或 `$TEMP`，**不要写 /tmp**：本环境 /tmp 是 MSYS 挂载点，
> 其目标由宿主会话动态决定且可能被回收，写操作会失败（报 No such file or directory）。

### 4.2 测试

| 文件 | 断言 |
|---|---|
| `internal/tools/tmphint_windows_test.go` | Windows 描述必须含 `/tmp` 与 `$TEMP`；`tmpHint()` 非空 |
| `internal/tools/tmphint_unix_test.go` | Unix 侧 `tmpHint()` 必须为空；描述**不得**混入 Windows 提示；但**必须**保留 `/tmp/`（`detachHint` 的 setsid 重定向依赖它） |

**变异验证**：把 Windows 的 `tmpHint()` 改成 `return ""` → 两个测试**立即变红**；还原 → 转绿。

### 4.3 对 Unix 侧**零影响**——逐字节证据

`tmpHint()` 被接进了跨平台的 `config.go`（共享文件），必须证明 Unix 侧描述**逐字未变**。
方法：同一份代码在 WSL 里跑两次（含 / 不含 `tmpHint()` 调用），对产出的描述原文做 `cmp`：

```
STEP1（变异：移除 tmpHint 调用）  描述长度 = 935 字节
STEP2（还原：含 tmpHint）         描述长度 = 935 字节

cmp -s desc_unix_with.txt desc_unix_without.txt  → IDENTICAL ✅

md5  78a867b2dc92fe3cae87303e749b8882  desc_unix_with.txt
md5  78a867b2dc92fe3cae87303e749b8882  desc_unix_without.txt
```

**md5 完全相同** → Unix 侧工具描述**逐字节未变**，KV 前缀稳定，无回归风险。

Unix 描述全文核验（确认该有的还在、不该有的没混进来）：

- ✅ 仍含 `/tmp/<名>.log`（`detachHint` 的 setsid 重定向用法，Unix 上 `/tmp` 真实可写）
- ✅ 不含 Windows 的「不要写 /tmp」提示

> **附带一桩实证**：本次探针把输出写到 WSL 的 `/tmp`，中间再取时**文件已消失**
> （`No such file or directory`）。改用 `$HOME` 后才稳定。
> 这是「`/tmp` 不可靠」在 **Linux 侧**也成立的一例——临时产物不要放 `/tmp`。

## 五、仍未解决的部分

- **若模型无视提示仍写 `/tmp`**，仍会失败。工具描述是软约束。
- **OkHuman 自己写脚本的位置**（`bash.go` 用 `os.TempDir()`）与 `/tmp` 可能是同一目录
  （Windows 上 `os.TempDir()` = `%TEMP%`，而 `/tmp` 常挂载到此处）→
  模型的 `rm -rf /tmp/*` 存在**误删正在执行的脚本**的自引用隐患。**尚未修复**，列为待办。

## 六、教训

1. **间歇性故障忌单次采样定论**。我曾因一次「恰好正常」的采样得出「无需修复」，
   直到观察到挂载目标被回收才锁定根因。
2. **控制变量实验优于机制推演**。四条「听起来合理」的因果链（login / TMPDIR /
   MSYS_TMP / TEMP）全部被一组四行实验证伪。
3. **二进制字符串扫描能一票否决**。`MSYS_TMP` 全目录 0 命中，直接否决方案，
   比读任何文档都快。
4. **`ls` 能列 ≠ 可写**；**同一命令上次成功 ≠ 这次成功**。测磁盘行为要真写，且要多次。
5. **改不动底层时，改行为层**。OkHuman 控制不了 MSYS 挂载，但控制得了给模型的提示词——
   这才是产品边界内真正有效的杠杆。
