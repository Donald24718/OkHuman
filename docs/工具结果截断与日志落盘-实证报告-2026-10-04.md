## 一、逻辑确实存在 —— 定位

用户记忆中的逻辑 = **工具结果超上限时，正文截断 + 全文落 log 文件 + 提示路径**，
并在 WebUI 上显示「**看到多少 / 全文多少 / 剩余被截断**」。

对应代码链路（三处）：

| 层 | 位置 | 常量/配置 | 作用 |
|---|---|---|---|
| **L1** 单流封顶 | `internal/tools/output.go` | `maxToolOutputBytes = 32 << 20`（32MB） | bash 的 stdout/stderr **各自**封顶 32MB，超出丢弃但持续读（管道不堵） |
| **L2** 回填截断 | `internal/agent/agent.go:617-622` | `ResultLimit`（默认 50000 字符，可配） | 工具结果回填给模型前截断，**全文落 log** |
| **L3** 后台存储截断 | `internal/background/background.go:139-141` | `maxStoredResultBytes = 256 * 1024`（256KB） | 后台任务表里的副本封顶，供 `/backgrounds` 查看 |

用户记忆的「可以看到多少、剩余的截断」= **L2** 这一层的产物，且 **WebUI 有专门显示**。

## 二、L2 核心逻辑（用户最关心的那层）

### 2.1 代码（`internal/agent/agent.go`）

```go
// §617：
if totalChars > opt.ResultLimit {
    // 截断：全文落 log 文件，正文留前 resultLimit 字符 + 一句 log 路径提示（模型用 bash 抓回）
    logPath := a.writeToolLog(opt, raw)
    truncated = true
    raw = utf16Slice(raw, opt.ResultLimit) +
        fmt.Sprintf("\n[已截断：完整结果 %d 字符在 %s，用 bash 的 cat / grep / tail 查看。]", totalChars, logPath)
}
// §625：事件带上 truncated / total_chars / content
emit(types.AgentEvent{"type": "tool_result", "name": tc.Function.Name,
    "truncated": truncated, "total_chars": totalChars, "content": raw})
```

### 2.2 落盘位置与命名（`writeToolLog`，§355）

```go
dir := filepath.Join(opt.DataDir, "tool-results")
ts  := time.Now().UTC().Format("2006-01-02_15-04-05")
path := filepath.Join(dir, fmt.Sprintf("tool-%s-%d.log", ts, toolLogSeq.Add(1)))
```

- 目录：`<dataDir>/tool-results/`
- 文件名：`tool-<UTC时间戳>-<单调序号>.log`
- **单调序号**（`toolLogSeq atomic.Uint64`）是 **2026-09-14 审计修**：
  旧实现文件名只有秒精度，同秒内两次截断（后台通知 goroutine 与轮内结果并发）会**撞名互相覆盖**，
  导致前一条消息里的 log 路径指向后一条的内容。

### 2.3 字符计量用 UTF-16 code units（不是字节、不是 rune）

```go
// utf16Len / utf16Slice（§760 / §772）
// 对齐 TS str.slice(0, n)：BMP 字符算 1，非 BMP（emoji 等）算 2。
```

→ 这保证**不会把一个 emoji 切成半个**（`utf16Slice` 在边界处回退到完整字符）。

### 2.4 与"后台通知"共用同一机制

`FormatBackgroundNotice`（§329）也用 `ResultLimit` + `writeToolLog`，
且**保留 head/tail 预算**：

```go
budget := opt.ResultLimit - utf16Len(head) - utf16Len(tail)  // 先扣头部状态行 + 尾部提示
if budget < 0 { budget = 0 }
return head + utf16Slice(result, budget) + tail
```

即：超长时总长仍控制在 `ResultLimit` 附近，头部状态行与尾部提示**一定保留**（不会被正文挤掉）。

## 四、"看到多少、剩余截断"在 WebUI 的显示（用户记忆的直接来源）

`webui/index.html:731-736`，`tool_result` 事件处理：

```js
case "tool_result": {
  const badge = [
    data.backgrounded ? "⏳ 已转后台" : "",
    data.truncated
      ? `截断 · 全文 ${fmtBytes(data.total_chars)} · 显示前 ${fmtBytes((data.content || "").length)}`
      : "",
  ].filter(Boolean).join(" · ");
  chatAddHtml(evCard("toolres", "📄", `${data.name} 返回`, data.content || "", badge || "完成"));
  break;
}
```

`fmtBytes`（§465）：`< 1024` → `n B`；`< 1MB` → `KB`；否则 `MB`。

**这正是用户记忆中"可以看到多少、剩余的截断"** ——
WebUI 卡片上会显示：**`截断 · 全文 XX KB · 显示前 YY KB`**。

## 五、三层机制总览（防止混淆）

| 触发场景 | 层 | 上限 | 超限后行为 | 用户可见性 |
|---|---|---|---|---|
| 命令输出 >32MB（单流） | L1 | 32MB | 丢弃超出但继续读；正文留前 32MB + **`[输出截断：…]` 说明放开头** | 结果正文里 |
| 工具结果 >`ResultLimit` | L2 | 默认 50000 字符 | 正文留前 N 字符 + **`[已截断：完整结果 X 字符在 <路径>…]`**；全文落 `tool-results/*.log` | 结果正文 + WebUI badge |
| 后台任务表副本 >256KB | L3 | 256KB | `capBytes` 截到 256KB（回退完整 UTF-8 边界）+ `\n[已截断]` | `/backgrounds` 端点 |

> **注意 L1 的说明放在开头**（`output.go:40` 注释：「说明放开头：agent 的 ResultLimit 截断保留头部，
> 模型据此知道丢弃量；尾部会被切掉」）—— 这是**有意设计**：因为 L2 只保留头部，
> 若 L1 的说明放尾部就会被 L2 切掉，模型就不知道 L1 丢了多少。
> **两层截断的提示位置是互相配合的。**
