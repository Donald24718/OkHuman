## 二、🔴 确证缺陷

### 缺陷 1（真 bug）：L3 `capBytes` 的 UTF-8 回退逻辑几乎完全失效

**位置**：`internal/background/background.go:147-157`

```go
func capBytes(s string, n int) string {
	if len(s) <= n {
		return s
	}
	cut := s[:n]
	for len(cut) > 0 && !utf8.RuneStart(cut[len(cut)-1]) {
		cut = cut[:len(cut)-1]
	}
	return cut
}
```

**根因**：循环判断"**最后一个字节**是否 rune 起始"，但剥掉一个字节后**新的结尾可能仍是续字节**——
判断维度用错了（应判断**边界后的第一个字节**是否续字节）。

**实证**（`s = "中文abc"`，9 字节）：

```
capBytes(n=1) = "\xe4"       合法UTF8=false   ← 半截
capBytes(n=2) = "\xe4"       合法UTF8=false
capBytes(n=3) = "\xe4"       合法UTF8=false   ← 本该是"中"（3字节）
capBytes(n=4) = "中\xe6"     合法UTF8=false   ← 半截
capBytes(n=5) = "中\xe6"     合法UTF8=false
capBytes(n=6) = "中\xe6"     合法UTF8=false   ← 本该是"中文"（6字节）

=== 正确实现应为 ===
proper(n=3) = "中"     合法UTF8=true
proper(n=6) = "中文"   合法UTF8=true
```

**影响**：L3 截断后的字符串是**非法 UTF-8** → 在 WebUI `/backgrounds` 响应里会导致
JSON 编码异常 / 页面乱码（`\ufffd` 替换字符）。**仅在后台任务结果恰好超 256KB 且边界落在多字节字符中间时触发**。

**修法**（一行）：
```go
cut := s[:n]
for len(cut) > 0 && !utf8.ValidString(cut) {   // 或：while n>0 && !utf8.RuneStart(s[n]) { n-- }
    cut = cut[:len(cut)-1]
}
```
更标准：
```go
for n > 0 && !utf8.RuneStart(s[n]) {
    n--
}
return s[:n]
```

> **严重性**：中。触发条件窄（需 >256KB 且边界切中文/emoji），但一旦触发就是可见的乱码。

### 缺陷 2（脆弱点）：L1 `cappedBuffer.Write` 违反 `io.Writer` 契约

**位置**：`internal/tools/output.go:23-34`

```go
func (c *cappedBuffer) Write(p []byte) (int, error) {
	room := c.cap - c.buf.Len()
	if room >= len(p) {
		return c.buf.Write(p)
	}
	if room > 0 {
		c.buf.Write(p[:room])
		p = p[room:]        // ← 重新切片，改变了 p 的 len
	}
	c.over += int64(len(p))
	return len(p), nil      // ← 返回的是【截断后】的长度，不是 len(p_原始)
}
```

**根因**：第 30 行 `p = p[room]` 后，第 33 行 `return len(p)` 返回**剩余长度**而非**原始长度**。

**实证**：
```
cap=5 写 10 字节 → Write 返回 n=5（应=10）
io.Copy(c, src) → 返回 n=900 err=short write   ← 契约违反
```

**为什么现在没炸**（重要）：
- **Unix 路径**：`cappedBuffer` 直接给 `os/exec` 的 `cmd.Stdout`，os/exec 内部 `io.Copy` 后
  **只在 `err != io.ErrShortWrite` 时才报错**（Go 标准库特意容忍）→ 实测 `cmd.Wait()` 无错误、输出精确完整。
- **Windows 路径**：`copyHandleTo`（`bash_windows.go:298`）**只看 error 不看 n** → 也不受影响。

**影响**：**当前生产行为正确，但靠标准库兜底**。风险：
- 若将来把 `cappedBuffer` 交给别的严格调用方（非 os/exec）→ 立即出错；
- Windows 侧 `copyHandleTo` 的 `continue` 分支（第 306 行）**生产不可达**（因为 `Write` 永不返回 error）→ 死代码，误导维护。

**修法**：保存原始长度，返回原始长度：
```go
func (c *cappedBuffer) Write(p []byte) (int, error) {
	orig := len(p)
	room := c.cap - c.buf.Len()
	if room >= orig {
		return c.buf.Write(p)
	}
	if room > 0 {
		c.buf.Write(p[:room])
	}
	c.over += int64(orig - max(room, 0))
	return orig, nil
}
```

> **严重性**：低-中。当前不影响生产，但是**潜在定时炸弹**，且已导致一处死代码。

### 缺陷 3（可用性）：磁盘写入失败时，提示里的"路径"是失败标记

**位置**：`internal/agent/agent.go:358-368`

```go
func (a *Agent) writeToolLog(opt RunOptions, full string) string {
	...
	return fmt.Sprintf("[文件写入失败：%s]", "写入失败")   // ← 返回的不是路径
}
```

而调用方（§619-621）**无条件把它当路径拼接**：
```go
logPath := a.writeToolLog(opt, raw)
raw = utf16Slice(raw, opt.ResultLimit) +
    fmt.Sprintf("\n[已截断：完整结果 %d 字符在 %s，用 bash 的 cat / grep / tail 查看。]", totalChars, logPath)
```

**实证**（只读目录触发）：
```
只读目录下写入 → 返回 "[文件写入失败：写入失败]"
回填模型的文本 = "XXXXXXXXXX\n[已截断：完整结果 100 字符在 [文件写入失败：写入失败]，
               用 bash 的 cat / grep / tail 查看。]"
```

**影响**：磁盘满/权限问题时，模型会被告知去 `cat [文件写入失败：写入失败]` ——
一个**不存在的路径**，浪费一轮工具调用，且模型**完全不知道全文已丢失**（以为还能找回）。

**修法**：调用方检查返回值来源（如返回 `(path string, ok bool)`），
失败时改为"全文落盘失败，仅保留前 N 字符"的诚实文案。

> **严重性**：中。磁盘异常时误导模型，且掩盖数据丢失。

### 缺陷 4（可用性）：路径未加引号，含空格时模型裸拼 `cat` 会失败

**位置**：同上 §621 的提示模板 + §340（后台通知同款）

**实证**：
```
提示 = "...完整结果 1 字符在 /tmp/.../a b/tool-results/tool-....log，用 bash 的 cat / grep / tail 查看。"
路径是否被引号包裹（供模型安全复制）= false
```

**影响**：`dataDir` 含空格（Windows 用户名常见，如 `C:\Users\John Doe\...`）时，
模型若执行 `cat C:\Users\John Doe\.okhuman-8451\tool-results\...` → **空格分词失败**。

**修法**：提示里给路径加双引号或反引号包裹。

> **严重性**：低-中。Windows 用户路径含空格时概率不低。

### 6.4 修复代码

**缺陷 1** — `internal/background/background.go`：
```go
func capBytes(s string, n int) string {
	if len(s) <= n {
		return s
	}
	// 边界 n 处若是续字节（0x80~0xBF），说明切在字符中间，向前退到字符起始。
	for n > 0 && !utf8.RuneStart(s[n]) {
		n--
	}
	return s[:n]
}
```

**缺陷 2** — `internal/tools/output.go`：
```go
func (c *cappedBuffer) Write(p []byte) (int, error) {

		return c.buf.Write(p)
```

## 七、结论

> **有效性**：截断逻辑**主路径（L2）完全有效**——端到端实测正确，UTF-16 截断安全，并发落盘无撞名。
>
> **缺陷**：排查出 **4 个缺陷**（1 真 bug + 1 脆弱点 + 2 可用性问题），
> **全部有可复现的实证测试**，并**已全部修复**（§6），每处修复均通过变异验证证明测试有效。
>
> **回归**：Windows + Linux 双平台 `vet` / `build` / `test` 全绿，格式合规，
> 原始风险（L3 中文乱码、io.Copy 报错、磁盘异常误导模型、空格路径不可复制）已消除。
